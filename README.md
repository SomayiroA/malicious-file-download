# Event ID 76 — Malicious File/Script Download Attempt 📁

## Short Overview of the Investigation

This investigation examines a medium-severity malware alert generated by LetsDefend's SOC137 detection rule. A suspicious macro-enabled Word document attempted to download a payload onto the workstation NicolasPRD.

My objective was to analyze the file, verify its malicious nature, determine whether the download was blocked, and investigate potential command-and-control (C2) communication.


## Alert Summary and Timeline ⚠️

### Alert
| Field | Details |
| ----- | ------- |
| EventID | 76 |
| Rule Name | SOC137 - Malicious File/Script Download Attempt |
| Severity | Medium |
| Event Time | March 14, 2021; 19:15 |
| Hostname | NicolasPRD |
| Source IP | 172.16.17.37 |
| File Name | INVOICE PACKAGE LINK TO DOWNLOAD.docm |
| MD5 | f2d0c66b801244c059f636d08a474079 |
| Device Action | Blocked |
| MITRE ATT&CK | T1204 - User Execution |

### Timeline ⌛
- *19:15*: The malicious file/script download alert was generated.
- *File analysis*: Threat intelligence and malware analysis identified malicious macro behavior involving PowerShell.
- *Log investigation*: Endpoint and network telemetry were examined for evidence of execution and communication with suspicious infrastructure.
- *Final assessment*: The download was blocked, but additional suspicious endpoint activity warranted further investigation.


## Investigation Steps 🕵️‍♂️

1. *Alert Triage*: I reviewed the alert metadata, affected host, file hash, filename, and device action. The blocked action indicated that the security control prevented the reported download.
2. *Malware Analysis*: I searched the file hash using VirusTotal and examined available sandbox and macro-analysis results. The document contained a macro designed to execute PowerShell and retrieve an additional payload from an external URL.
3. *Endpoint and Network Investigation*: Reviewed endpoint command history and network logs for evidence of payload execution or contact with suspicious infrastructure. The available network investigation showed no confirmed connection to the identified C2 infrastructure. However, other suspicious command activity required further examination.


## My Findings, Conclusions, and Recommended Response 🔬

### Findings 
- The document was identified as malicious.
- The endpoint security control recorded the download as Blocked.
- Macro analysis indicated an attempted PowerShell-based payload download.
- No confirmed communication with the identified C2 infrastructure was found in the reviewed network logs.
- Additional suspicious endpoint activity meant the host should not automatically be considered clean.

### Conclusion
The alert was classified as a True Positive - Blocked malicious download. Although the reported download was blocked, the endpoint should receive further investigation before being declared uncompromised.

### Recommended Response
1. I quarantined the host machine, deleted the malicious file and searched for related copies.
2. I nvestigated suspicious PowerShell commands, DLL execution, and potential persistence mechanisms.
3. I verified whether the endpoint communicated with any identified malicious infrastructure.
4. I contained NicolasPRD while investigating any unresolved indicators of compromise.
5. I documented the evidence and closed the incident only after the host's status has been established.

# Lessons Learned 🌿

- A blocked download does not automatically prove that an endpoint is uncompromised.
- Macro-enabled documents can execute PowerShell to retrieve additional payloads.
- File hashes and sandbox reports help establish whether a file is malicious.
- Correlating endpoint and network logs helps determine whether malicious activity progressed beyond the initial attempt.
